# Pi public RPC bridge

English | [中文](README.zh.md)

The bridge connects an unmodified, independently installed official Pi Coding Agent to Electron and local Web. [version.json](version.json) versions the bridge separately and records the tested Pi release. Conversation execution uses public CLI RPC; provider setup uses an independent Node worker and the same selected package’s public ModelRuntime SDK export. Electron and React import neither Pi SDK classes nor private implementation modules.

[process.ts](process.ts) owns the subprocess, public LF-delimited JSONL transport, request correlation and joined shutdown. The CLI's `get_state` response establishes readiness. Unicode separators inside strings remain data. Read-only metadata requests have a host deadline; interactive commands wait for Pi's actual response without a default deadline so human dialogs and long operations can complete. Closing stdin requests Pi's orderly shutdown; a bounded escalation terminates a non-exiting process and still awaits its close event. Command rejection and unexpected process exit reject outstanding requests.

[manager.ts](manager.ts) projects native message, tool, queue, compaction and extension UI records into [PiSnapshot](types.ts). Native compaction and branch summaries remain visible. An assistant message with `stopReason: 'aborted'` retains its partial output without raising a failure notice; a provider error before any text remains in the transcript. Final messages are authoritative; deltas and `thinking_end` update streaming content. Responses summaries use ordinary thinking blocks; token usage supplies no missing text. The [Responses flow test](../tests/responses-flow.test.ts) verifies Pi 0.99.1 summaries with and without deltas, tool execution, empty summaries and native history. `agent_settled` triggers an authoritative refresh before publishing idle. The active entry branch supplies full history, including messages before compaction. Existing session files reuse a live process, including simultaneous open requests. Sidebar discovery only reads native JSONL metadata; Pi owns writes, context reconstruction and migrations.

Steering enters at Pi’s next supported turn boundary without interrupting a running tool. Abort preserves unconsumed inputs; clear_queue removes them. Extension select/confirm/input/editor dialogs use public responses; notifications, text statuses and widgets are projected, while arbitrary terminal components remain unsupported. Active conversations use Pi’s available models and thinking levels. Provider inventory is available before project selection; a pending model choice becomes public `set_model` when a new conversation opens. New drafts expose thinking choices from the selected SDK's public model metadata (`reasoning` and `thinkingLevelMap`) and native settings. The first send applies an explicit draft choice through `set_thinking_level` after model selection; reopening history leaves its thinking level intact. The [catalog test](../tests/provider-catalog.test.ts) compares draft choices and defaults with actual Pi 0.99.1 RPC.

[providers.ts](providers.ts) owns the independent management process and safe login attempts. [provider-runtime.ts](provider-runtime.ts) resolves the selected official CLI’s public package export and independent Node; it never substitutes another installation’s SDK. [provider-worker.ts](../runtime/provider-worker.ts) calls public ModelRuntime login/logout and forwards Pi prompt, browser-link, device-code and cancellation callbacks. Pi writes credentials through its authentication storage. Custom endpoint edits validate and atomically update non-secret `models.json` fields while preserving unrelated providers, fields and symlink targets. The resolved agent directory defaults to `~/.pi/agent`, with runtime/environment overrides shared by RPC. Worker/SDK files stay outside ASAR and GUI dependencies; wrappers, incompatible SDK exports and extension registrations use native Pi setup.

[provider-catalog.ts](provider-catalog.ts) projects expandable provider model lists. The worker returns each public provider catalog separately from available models, with network discovery disabled. For an open chat, public RPC models replace the same provider’s catalog and include extension-only providers; this does not imply stored credentials or SDK management support. Settings never load extension code or probe compatible endpoints. [provider-catalog.test.ts](../tests/provider-catalog.test.ts) verifies native registrations, model selection and unchanged static configuration against Pi 0.99.1.

Runtime selection belongs to [runtime/config.ts](../runtime/config.ts). `pnpm pi:install [version/latest]` independently installs and verifies an exact official package under ignored `.pi-runtime/<version>`. `runtime/selected.json` or `PI_DESKTOP_RUNTIME_CONFIG` selects command, arguments, environment and agent directory. Without a selection, explicit `PI_EXECUTABLE` precedes the versioned offline bundled installation; there is no implicit PATH lookup. `mode: bundled` follows the current distribution's default and takes priority over environment selection. `pnpm pi --version`, official TUI, RPC and provider worker use the same selected installation.

[pi-session-controls.ts](../runtime/pi-session-controls.ts) registers the public `desktop-session` extension command. Pi 0.99.1 has no `navigate_tree` RPC command; its public command context supplies `navigateTree(entryId, { summarize: false })` and `fork(entryId, { position: 'at' })`, including assistant entries. The bridge requires that command and blocks execution, queued input, dialogs and overlapping commands before navigation. Pi writes branches and new session files; the bridge refreshes native entries and leaf identity after the command. The compiled extension is a real packaged resource outside ASAR. [pi-flow.test.ts](../tests/pi-flow.test.ts) verifies intermediate assistant tool-call navigation, return to the final reply, and user/assistant forks with no extra provider requests and an intact original session. Native afterPack runs this same flow against actual Resources.

The compatibility record currently covers official `@earendil-works/pi-coding-agent` 0.99.1, Git revision `d86654abb8862e201933517d6f1fce9f88dd117f`, against bridge 1.15.0. Executed evidence runs [compat.ts](../runtime/compat.ts), [bridge.test.ts](../tests/bridge.test.ts) and [pi-flow.test.ts](../tests/pi-flow.test.ts) through Node with `--import tsx`. The actual Pi flow uses an isolated loopback streaming provider to exercise Pi's real write/read/shell tools, filesystem results, partial assistant output, natural steering and follow-up delivery, cancellation of the HTTP request, preserved queued inputs, queue clearing, native clone/fork/switch, session discovery and restart/resume. A public extension loaded by the actual CLI verifies confirm/select/input/editor responses, notification and persisted custom output without a model run. Two independent engine flow copies passed concurrently. [pi-flow.expected.json](../tests/fixtures/pi-flow.expected.json) records the visible transcript and file results. Windows fixtures explicitly select Pi's PowerShell tool; POSIX fixtures use the default bash tool and portable echo. Actual Windows/Linux execution, external live providers and application packaging are separate checks, not established by these macOS engine tests.

Before selecting another Pi release, compare public RPC, CLI/resource/session documentation and the exported authentication SDK with this bridge. Run `pnpm test:compat` against the actual executable and the owning provider/flow tests, then record actual results. RPC compatibility alone does not establish provider SDK compatibility; unsupported management keeps the native setup route. [pi-fixture.ts](../tests/pi-fixture.ts) supplies a disposable official-Pi workspace and scripted streaming provider for GUI verification. No upstream source modification or hidden model context is part of compatibility.

Sidebar discovery accepts registered project roots together, scans shared native session directories once, and resolves project-relative session directories independently. Project aliases, collapse, pin and archive state stay in Host GUI preferences; discovery does not rewrite Pi sessions.

[agent-configuration.ts](../runtime/agent-configuration.ts) projects package manifests and native resource filters. Package installation/update/removal runs in [package-worker.ts](../runtime/package-worker.ts) under the selected Node/public SDK, with fd 3 isolated from npm/Git stdout. [package-operation.ts](../runtime/package-operation.ts) owns cancellation and joined process-tree teardown. Updates use a memory-only native settings selection to preserve scope; toggles update the owning package filters. [Extension compatibility](../../../docs/pi-desktop/extensions.md) records the default collection and tested RPC limits.

[Skill presentation](skill-presentation.ts) recognizes Pi 0.99.1’s native skill envelope without editing messages or importing SDK code. Unknown formats remain visible as plain text. [Package discovery and management](../../../docs/pi-desktop/extensions.md#marketplace) keeps public gallery metadata separate from native package execution.

[session-records.ts](session-records.ts) reads listed Pi v3 session files before RPC startup, using the persisted last entry and parent chain with the same message projection as live history. It never executes extensions, writes sessions or migrates records. Unknown versions, incompatible trees and files over 64 MiB defer to Pi. The first live snapshot supersedes the preview; execution controls require a live handle. [session-preview.test.ts](../tests/session-preview.test.ts) compares the preview with actual Pi 0.99.1 RPC while an extension startup barrier is held, including unchanged file bytes.

The optional `contextUsage` projection comes only from public `get_session_stats`. The bridge refreshes it after messages and alongside native state; a newer request supersedes older results. Invalid or unsupported metadata leaves it unavailable without failing the chat. Native null usage after compaction remains null; cumulative session token totals never stand in for current context. [bridge.test.ts](../tests/bridge.test.ts) checks missing, valid, null and invalid records; [pi-flow.test.ts](../tests/pi-flow.test.ts) compares the projection against actual Pi 0.99.1 and verifies a visible `@path` prompt reaches Pi unchanged before its native file tool runs.

The composer reads `completedContext`, a copy of the usage, composition and cache rate taken after public `agent_settled` and authoritative idle-state refresh. It stays absent before the first complete assistant reply, stays unchanged during tools, streaming, cancellation and idle metadata updates, and resets for a new native session. Loading completed native history restores the display without rewriting that history. [context-settlement.test.ts](../tests/context-settlement.test.ts) verifies first-turn tool boundaries, later streaming, cancellation and resume against actual Pi 0.99.1.

The owned extension publishes numeric-only `contextBreakdown` weights through public `setStatus`; no prompt, tool definition or message text enters that metadata or native history. It reads the effective prompt, active tool metadata and Pi's compaction-aware session context at startup, history/model changes and settlement, and observes current messages before model calls. The GUI normalizes text/schema character counts into approximate shares, descending by size; images have a fixed weight, and MCP tools reached only through codemode remain part of that active tool's definition. Unknown total usage hides the breakdown. [context-composition.test.ts](../tests/context-composition.test.ts) covers categorization, native summaries, hidden shell output, images and invalid metadata; the actual Pi flow verifies the projection and unchanged model requests.

The **Cache hit rate** footer uses public session token totals: `cacheRead / (input + cacheRead + cacheWrite)`. Pi input excludes cache reads/writes; output tokens do not enter the denominator. The ratio is weighted by input size across all native session entries, including inactive branches and compacted history. Missing, invalid or zero-total usage displays a dash; a measured zero cache read displays 0%. [cache-usage.test.ts](../tests/cache-usage.test.ts) covers these boundaries, and the real Pi flow verifies provider cache details survive normalization and aggregation.

Completion observers receive only the persisted final assistant entry after public `agent_settled`. The Host watches all owned Pi sessions, including sessions without a renderer subscription. [unread-chats.ts](../unread-chats.ts) serializes atomic writes to `unread-chats.json` under the GUI home and retains one entry per native session identity, with canonical file paths. Read receipts include the displayed entry ID, so a late receipt cannot clear a newer reply. The shared GUI acknowledges only focused, visible, unobscured conversations containing that entry. Its validated macOS preload action sends the unread count to Electron’s native Dock badge; Web keeps sidebar indicators. [unread-host.test.ts](../tests/unread-host.test.ts) verifies actual Pi publication, restart, stale receipts and unchanged native session bytes; the client and storage tests cover focus, visibility, deduplication, failed writes and shutdown.

[Session titles](../runtime/session-title.ts) use the selected model through Pi 0.99.1’s public `modelRegistry.streamSimple` after `agent_settled`. One background request summarizes the first human message, targeting five words or ten CJK characters; it has no tools and never enters the main transcript or context. Input is capped at 12,000 characters, output requests 256 tokens, and cancellation has a 60-second deadline. Public `setSessionName` persists the accepted title and emits `session_info_changed`. Existing names, including manual edits made during generation, win; replacement and shutdown abort and join the request. Failure retains the first-message fallback without retrying in that open session. Discovery and resume alone never request titles. [session-title-flow.test.ts](../tests/session-title-flow.test.ts) verifies streaming/tool timing, a held auxiliary request, unchanged conversation/context, sidebar discovery and native resume against actual Pi; native afterPack also runs it. Context estimates use the public read-only `buildSessionProjection().messages`, equivalent to the selected release’s session-context messages.
